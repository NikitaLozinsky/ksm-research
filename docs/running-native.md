# Запуск на нативном Arch Linux

[Общая инструкция по воспроизведению](REPRODUCE.md)

Инструкция для повтора экспериментов на «железе» (не в ВМ). Все скрипты те же, что на ВМ. Тип системы определяется автоматически (`systemd-detect-virt`), снимок окружения пишется в `env/native/`.

## Что скрипты меняют в системе (и что возвращают)

| Что | Когда | Возврат |
|---|---|---|
| `/sys/kernel/mm/ksm/*` (run, pages_to_scan, advisor, max_page_sharing и т.д.) | перед каждым прогоном | при **любом** выходе из скрипта (конец, ошибка, Ctrl+C, SIGTERM) восстанавливаются **исходные** настройки, сохранённые при старте (`safety_init` в `scripts/lib/common.sh`) |
| слитые страницы KSM | перед каждым прогоном `run=2` | если KSM уже использовался до запуска, его страницы будут разъединены (preflight предупреждает); после восстановления исходного `run=1` ksmd сольёт их заново |
| `drop_caches` | перед каждым прогоном | не требуется: сбрасывается только кэш, данные не теряются, система лишь временно медленнее читает файлы |
| контейнеры podman | только с меткой `ksm-research=1` | останавливаются и удаляются только они. **Чужие контейнеры не трогаются** |
| perf (system-wide трассировка) | в сериях с трассировкой | останавливается при любом выходе |

Скрипты **не трогают** загрузчик, параметры ядра, zram/swap, THP, сеть, sshd, cpufreq.

## Порядок

```bash
cd ~/ksm-research
```

1. Установить пакеты (те же, что на ВМ; версии будут записаны в `env/native/packages.txt`):

```bash
sudo pacman -S --needed podman stress-ng sysstat perf asciinema tmux jq python-numpy python-pandas python-matplotlib python-scipy nodejs jdk-openjdk htop gcc linux-docs rt-tests man-db man-pages poppler
```

2. Скачать образ для контейнерных тестов (нужна сеть):

```bash
podman pull docker.io/library/alpine:3.22
```

3. Проверка системы, только чтение. Нужен итог без FAIL; WARN прочитать и решить:

```bash
scripts/preflight.sh
```

4. Посмотреть план, ничего не запуская:

```bash
scripts/run-all.sh --dry-run
```

5. Запустить в tmux (переживёт закрытие терминала):

```bash
scripts/tmux-run.sh all scripts/run-all.sh
```

6. Ждать окончания (печатает только итог):

```bash
scripts/tmux-wait.sh all
```

Чтобы выбрать серии, перечислите их: `scripts/run-all.sh inherit jitter` (список — `scripts/run-all.sh --list`).

## Рекомендации для чистоты замеров на железе

- Закрыть браузер, IDE, клиент Claude и другие активные программы. На ВМ агент в той же системе давал 3–4 % ЦП фона (`docs/limitations.md`, Л1а).
- Ноутбук подключить к сети питания. Профиль питания записывается в `env/native/` (cpufreq), но не меняется скриптами.
- Не пользоваться машиной во время серии.
- Сторож памяти: задайте `MIN_AVAIL_MIB=2000` в окружении, и серия прервётся сама (с восстановлением KSM), если свободной памяти станет меньше порога.

## Если что-то пошло не так

- Серию прервали или машина зависла: при следующем запуске preflight покажет оставшиеся контейнеры эксперимента, `reset_state` их удалит. Вернуть KSM в исходное состояние вручную: `echo 2 | sudo tee /sys/kernel/mm/ksm/run`, затем выставить прежние значения (исходные значения видны в первом `.json` серии, блок `ksm`).
- Логи серий: `results/logs/<имя>.log`, код выхода — `results/logs/<имя>.exit`.

## Этап 2 на нативной системе (задержка под нагрузкой)

1. Собрать образы нагрузок (нужна сеть): `scripts/build-workloads.sh`. Digest образов запишутся в `env/native/images.txt`.
2. Проверить генератор на эталоне: `scripts/run-all.sh loadgen-check` (ожидается `ИТОГ: PASS`).
3. **Частоты запросов подобрать заново** пилотом (`scripts/run-all.sh load-pilot`, затем `scripts/stage2-load-pilot-summary.py`). На железе насыщение будет при других частотах, чем на ВМ (на ВМ: nginx 400, Python 50, Node.js 200, JVM 400, PostgreSQL 200 на контейнер). Выбранные частоты передать в `RATE_*` при запуске серии `load`.
4. Порядок по приоритету (короткие и самые информативные — первыми): `xcheck` → `cow-cost` → `ksmd-tlb` → `ksmd-pin` → `load`.
5. Известное по ВМ: JVM в первые десятки секунд под нагрузкой прогревает JIT, и базовая фаза серии `load` искажается (`docs/decisions.md`, Р22). При повторе на железе прогрев нужно делать под нагрузкой.
