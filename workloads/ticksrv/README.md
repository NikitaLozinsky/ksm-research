# Три нагрузки с фиксированным тиком

| Нагрузка | Действие в каждом тике | Настройка силы нагрузки |
|---|---|---|
| C, 60 Гц | Записи в детерминированный мир размером 16 МиБ и целочисленная работа симуляции | `TICK_WRITES` (128 страниц за тик), `TICK_CPU_WORK` (0 итераций) |
| Luanti 5.17, 20 Гц | Движение сущностей и изменения узлов в активном блоке | `TICK_LUANTI_ENTITIES` (64), `TICK_LUANTI_EDITS` (32) |
| Godot 4.7, 60 Гц | Расчёт управляющих сил и применение их к телам в headless-проекте | `TICK_GODOT_BODIES` (128), `TICK_GODOT_PASSES` (1 итерация на тело) |

У Luanti и Godot в процессе остаётся детерминированный снимок состояния размером 8 МиБ. Каждый контейнер запускает отдельный экземпляр через `ksm_launch`, с отключённой сетью. Варианты одного повтора идут парами, порядок нагрузок и режимов внутри пары определяется `SEED`. Перед каждым прогоном выполняется общий сброс состояния.

## Воспроизведение из fish

Сборка образа с пакетами Arch Linux:

```fish
bash ~/ksm-research/scripts/build-ticks.sh
```

Быстрая проверка одного экземпляра каждого движка:

```fish
bash ~/ksm-research/scripts/tests/check-ticks.sh
```

На нативном хосте серия запускается через общую обёртку питания. Команда запускает шесть дымовых прогонов по восемь контейнеров, с фазами 10/30/12 с и прогревом 5 с.

```fish
systemd-run --user --unit=ksm-s4-ticks-smoke --collect --setenv="PATH=$PATH" bash ~/ksm-research/scripts/series-guard.sh ~/ksm-research/scripts/stage4-ticks.sh
```

Из другого терминала можно следить за сборкой, проверкой или дымовой серией. Укажи соответственно `build`, `check` или `smoke`:

```fish
bash ~/ksm-research/scripts/watch-ticks.sh smoke
```

Ctrl+C завершает наблюдение. Для остановки самой серии с восстановлением настроек есть общая команда:

```fish
bash ~/ksm-research/scripts/stop-series.sh
```

В пилоте `WORKLOADS` задаёт список нагрузок. При `TICK_CALIBRATE=1` каждый повтор проверяет одну точку калибровки при выключенном KSM. Списки точек задаются `TICK_CPU_STEPS`, `TICK_EDIT_STEPS` и `TICK_PASS_STEPS`. Для серии с именем `stage4-ticks-calibration*` или `stage4-ticks-pilot*` наблюдение выводит:

```fish
bash ~/ksm-research/scripts/watch-ticks.sh pilot
```

Серию Б запускает `scripts/stage4-block-b.sh` с настройками Р25. Пример первой дневной части:

```fish
systemd-run --user --unit=ksm-s4-block-b-1 --collect --setenv="PATH=$PATH" --setenv=REP_START=1 --setenv=REP_END=3 powerprofilesctl launch -p performance -r 'KSM tick series B' -i ksm-research bash ~/ksm-research/scripts/series-guard.sh ~/ksm-research/scripts/stage4-block-b.sh
```

Монитор оставшихся 130 прогонов этапа 4. Команду можно оставить открытой между дневными частями. Время остатка — машинное, без пауз. При расчёте сводки монитор показывает прошедшее и CPU-время, а также число обработанных прогонов, если сводка начала писать прогресс. Ctrl+C завершает монитор.

```fish
python3 ~/ksm-research/scripts/watch-stage4.py
```

## Данные

Сырые CSV в `results/raw/stage4-ticks-smoke/<время>/`. `params.json` хранит выбранные параметры, версии пакетов, ID образа и PID контейнеров. `clocks.csv` хранит метки фаз и пары часов для объединения тиков с `perf-script.txt.gz` и `vmstat.csv`. `mem.csv` хранит `ksm_merging_pages` по контейнерам, а `world-ksm.csv` — страницы конкретного отображения мира C-сервера.

Сводка `scripts/stage4-ticks-summary.py` строится после сбора данных. Длительность работы — разность меток начала и конца; межтиковый интервал — разность начал двух соседних тиков в одном контейнере. Для 1 % low берётся обратное среднее самых длинных 1 % интервалов. Пропуском считается интервал больше 1,5 номинального периода. Интервалы, пересекающие границу фазы, исключаются. В атрибуции длительные окна работы и длинные межтиковые интервалы сравниваются с окнами той же длины в случайные моменты фазы. Ограничения измерения описаны в [Л14](../../docs/limitations.md#л14-границы-измерения-тика-в-luanti-и-godot).
