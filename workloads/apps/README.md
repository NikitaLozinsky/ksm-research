# Реальные нагрузки для этапа 1

Пять классов приложений из темы работы. Каждое запускается в контейнере podman, KSM включается лаунчером **внутри** контейнера (`/ksm/ksm_launch`, `docs/decisions.md` Р11). Каталог `workloads/ksm-probe/bin` монтируется в `/ksm` только для чтения.

| Имя | Образ | Что внутри | Почему такое |
|---|---|---|---|
| `nginx` | `docker.io/library/nginx:1.27-alpine` (официальный) | nginx, конфиг по умолчанию, worker-ы по числу ЦП | веб-сервер, мало анонимной памяти: нижняя граница выгоды |
| `python` | `localhost/ksm-python` (`python/Containerfile`) | gunicorn, 2 worker-а, Flask + numpy | интерпретатор: импортированные модули лежат в анонимной куче, одинаковой у всех экземпляров |
| `node` | `localhost/ksm-node` (`node/Containerfile`) | Node.js + express | V8: куча и JIT-код в анонимной памяти |
| `jvm` | `localhost/ksm-jvm` (`jvm/Containerfile`) | JRE 21, HTTP-сервер на `com.sun.net.httpserver`, справочник 200 тыс. записей в куче | JVM: метаданные классов, JIT, куча |
| `postgres` | `docker.io/library/postgres:17-alpine` (официальный) | PostgreSQL, настройки по умолчанию | СУБД: основная память (`shared_buffers`) — разделяемая (shmem), а не анонимная приватная, поэтому KSM её не сливает. Ожидается малая выгода, это осознанный «отрицательный» класс |

Версии базовых образов зафиксированы тегами, а digest каждого образа пишется в JSON прогона.

Важно: исполняемый код и библиотеки (файловые страницы) KSM не трогает. Одинаковые образы уже делят page cache через общие слои overlayfs. Выгода KSM — только в анонимной памяти процессов (куча, JIT, структуры интерпретатора).
